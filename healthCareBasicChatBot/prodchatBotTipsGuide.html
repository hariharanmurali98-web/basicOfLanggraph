Production Conversation Memory Architecture

Big Misconception Beginners Have

Many beginners store chat history in a Python list: 

conversation_history = []

This works only for learning and small demos.

In real production systems this approach is never used.

Reasons:
  • Data is lost when server restarts.
  • Cannot scale across multiple servers.
  • History becomes extremely large.
  • Causes high token costs.
  • Can exceed model context windows.

How Chat History is Stored

Every conversation receives a unique identifier.

Examples:
  • thread_123
  • session_456
  • user_999_chat_11

Example

session_id = "user_102_chat_456"

Whenever the user sends a question:

  1. Fetch recent messages using session_id.
  2. Convert data into message objects.
  3. Send messages to LLM.
  4. Receive response.
  5. Persist both user and AI messages.

Why LangGraph is Popular

LangGraph provides built-in conversation persistence.

Instead of manually loading and saving messages, LangGraph can automatically restore state by thread ID. 

config = {
    "configurable": {
        "thread_id": "session-user-9823"
    }
}

response = await graph.ainvoke(
    {
        "messages":[
            HumanMessage(content=user_query)
        ]
    },
    config=config
)

What Happens Internally

  • Graph loads previous conversation.
  • Graph reconstructs state.
  • New message gets appended.
  • Model is invoked.
  • Checkpoint gets updated.

Problem: Context Overflow

Most beginners assume every message should be sent to the model every time.

Production systems never do that.

Large histories cause:
  • Higher costs
  • Higher latency
  • Context window overflow
  • Poor performance

Strategy 1: Sliding Window Memory

Keep only the most recent messages.

Example: 

System Message

User Question 8
AI Response 8

User Question 9
AI Response 9

User Question 10
AI Response 10

Messages 1-7 are excluded from model input.

Best for:

  • Customer Support
  • Helpdesk Agents
  • Ticket Systems
  • FAQ Bots

Strategy 2: Rolling Summarization

Older conversations are compressed into a summary. 


Summary:
User previously discussed a home loan,
submitted salary proof,
and requested EMI calculations.

Recent Messages:
21
22
23
24
25

Effective for:

  • Healthcare Agents
  • Financial Advisors
  • Legal Assistants
  • Long Running Conversations

LangChain Message Trimming

from langchain_core.messages import trim_messages

trimmer = trim_messages(
    max_tokens=2000,
    strategy="last",
    token_counter=llm,
    include_system=True,
    allow_partial=False,
    start_on="human"
)

Key Parameters

  • max_tokens → Maximum context size
  • strategy="last" → Keep most recent messages
  • include_system → Preserve important instructions
  • start_on="human" → Ensure valid conversation order

Final Revision Summary

✅ Do not store production chat history in Python lists

✅ Store messages using thread_id or session_id

✅ Use Redis for active memory

✅ Use PostgreSQL for durable storage

✅ Use LangGraph Checkpointers for persistence

✅ Trim messages before every LLM call

✅ Keep SystemMessage permanently

✅ Use summaries for very long conversations

✅ Convert DB rows back into HumanMessage, AIMessage and SystemMessage objects before invoking the model
