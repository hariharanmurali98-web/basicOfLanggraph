Core Concept

The Biggest LangGraph Concept: State

Everything in LangGraph revolves around State. Think of State as a shared notebook that travels through the graph.

Node A | v Node B | v Node C

Each node in the pipeline can:

  • Read State
  • Modify State
  • Return Updated State

Before LangGraph

response = llm.invoke(
    [HumanMessage(content="What is RAG?")]
)
Question | v LLM | v Answer

LangGraph Flow

Question | v State | v Node 1 | v Node 2 | v Node 3 | v Answer
Key Architectural Shift: In LangGraph, the LLM is no longer the entire application wrapper; it is simply one part of a larger workflow.

Concept 1: State

State holds the structured data schema that all components interact with.

Minimal State Example

from typing import TypedDict

class State(TypedDict):
    question: str

# State instance
state = {
    "question": "What is RAG?"
}

More Realistic State

from typing import TypedDict

class State(TypedDict):
    question: str
    answer: str

# State instance
state = {
    "question": "What is LangGraph?",
    "answer": ""
}

Why State Exists

Without State:
Node A doesn't know what Node B did.
With State:
Node A | | updates state v Node B | | reads state v Node C All nodes share information.

Concept 2: Nodes

A node is usually just a Python function that consumes the current state and returns state changes.

def chatbot(state):
    state["answer"] = "LangGraph is used for AI workflows."
    return state
State | v chatbot() | v Updated State

Concept 3: StateGraph

A graph needs a structure. StateGraph acts as your workflow blueprint.

from langgraph.graph import StateGraph

# Initialize graph with your schema
graph_builder = StateGraph(State)

Defining Nodes on the Blueprint

from typing import TypedDict
from langgraph.graph import StateGraph

class State(TypedDict):
    question: str
    answer: str

def chatbot(state):
    state["answer"] = (
        "LangGraph is a framework for AI workflows."
    )
    return state

graph_builder = StateGraph(State)

# Add our node to the blueprint
graph_builder.add_node("chatbot", chatbot)

Concept 4: START and END

Every workflow requires an explicit beginning and ending point.

from langgraph.graph import START, END

# Hooking up workflow edges
graph_builder.add_edge(START, "chatbot")
graph_builder.add_edge("chatbot", END)
START | v chatbot | v END
Putting It Together

Complete First LangGraph Program

from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    question: str
    answer: str

def chatbot(state):
    state["answer"] = f"You asked: {state['question']}"
    return state

# 1. Blueprint creation
graph_builder = StateGraph(State)

# 2. Add nodes
graph_builder.add_node("chatbot", chatbot)

# 3. Add edges
graph_builder.add_edge(START, "chatbot")
graph_builder.add_edge("chatbot", END)

# 4. Compile workflow
graph = graph_builder.compile()

# 5. Invoke graph
result = graph.invoke(
    {
        "question": "What is LangGraph?",
        "answer": ""
    }
)

print(result)

Output

{
    'question': 'What is LangGraph?',
    'answer': 'You asked: What is LangGraph?'
}

Real LangGraph with ChatGroq

Connecting real LLM calls inside your graph nodes.

from dotenv import load_dotenv
from langchain_groq import ChatGroq

load_dotenv()

llm = ChatGroq(model="openai/gpt-oss-20b")

def chatbot(state):
    response = llm.invoke(state["question"])
    return {
        "answer": response.content
    }

The Most Common State in LangGraph: Messages

Instead of single strings for question and answer, production graphs track complete message streams:

from typing import TypedDict
from langchain_core.messages import BaseMessage

class State(TypedDict):
    messages: list[BaseMessage]

This forms the foundation of Chatbots, Agents, Memory, and Multi-Agent Systems.

Message-Driven Node Implementation

# State holds message instances:
state = {
    "messages": [
        HumanMessage(content="Hello")
    ]
}

# The node processes the full context and records the response:
def chatbot(state):
    response = llm.invoke(state["messages"])
    state["messages"].append(response)
    return state
Direct Link to Prior Lessons: This is why mastering HumanMessage, AIMessage, and SystemMessage matters—LangGraph standardizes state passing around sequences of these message types.

What to Learn Next

Master these foundational components in sequence:

  1. TypedDict — Defining structured State schemas (class State(TypedDict):)
  2. Nodes — Writing update functions (def chatbot(state):)
  3. START — Designating the entry point
  4. END — Designating the exit point
  5. StateGraph — Instantiating the blueprint (StateGraph(State))
  6. compile() — Locking and preparing the graph executable (graph_builder.compile())
  7. graph.invoke() — Executing the pipeline with initial state

The Production Path Ahead

State with Messages ↓ Chatbot Graph ↓ Memory ↓ Checkpointer ↓ thread_id ↓ Production LangGraph

This transition path leads directly into checkpointer architectures, multi-tenant thread persistence, and production backends like Postgres and Redis.
