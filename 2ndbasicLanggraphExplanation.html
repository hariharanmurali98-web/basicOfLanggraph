LangGraph State Deep Dive

Mastering Annotated, Reducer Functions, and State Merging Behavior.

Concept 1

Why Annotated?

messages: Annotated[
    list,
    add_messages
]
Normal List + Special LangGraph Behavior

Without Annotated:

messages: list

LangGraph treats the field as a plain dictionary value. It doesn't know how to merge updates between node runs, so any new return value completely overwrites the existing list.

Concept 2

Why add_messages?

Suppose your graph starts with this initial state:

[
    HumanMessage(content="Hello")
]

Your node executes and outputs:

[
    AIMessage(content="Hi")
]
Without add_messages (Default Overwrite) 
[
    AIMessage("Hi")
]

❌ Old message lost: Prior conversation history is completely wiped out.

With add_messages (Reducer Behavior) 
[
    HumanMessage("Hello"),
    AIMessage("Hi")
]

✅ Old messages preserved: LangGraph merges and retains full context.

Concept 3

What Happens Internally?

Tracing the state transition step-by-step:

1. Input State to Node

{
    "messages": [
        HumanMessage(content="Hi")
    ]
}

2. Value Returned by Node

{
    "messages": [
        AIMessage(content="Hello")
    ]
}

3. LangGraph Merges Automatically via Reducer

{
    "messages": [
        HumanMessage(content="Hi"),
        AIMessage(content="Hello")
    ]
}
Concept 4

Why Is This Important?

Almost every production LangGraph application standardizes on this state schema:

class State(TypedDict):
    messages: Annotated[
        list,
        add_messages
    ]

This single schema pattern powers:

  • Chatbots
  • Agents
  • Tool Calling
  • RAG Architectures
  • Multi-Agent Systems
  • Memory & Checkpointing

Interview Takeaway

Question: "Why do we use Annotated[list, add_messages] in LangGraph?"

add_messages acts as a reducer. Instead of replacing the existing messages list, it automatically appends new messages returned by nodes. This allows conversation history to be preserved across graph execution.

def chatbot(state):
